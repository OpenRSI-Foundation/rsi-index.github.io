Tasks

Signature tasks, 1-node tasks, and the taxonomy behind them.

Every task follows the same structure: a pinned repository, a task-pristine human baseline, an agent research loop, and an independent final verifier. Gains are measured against the original authors' recipe, rerun frozen in the same environment.

Framework v0.1 · updated Aug 2026

Signature tasks

One signature task per domain.

The signature tasks are the program's deepest environments, built as complete Harbor packages with hardened, adversarially tested verifiers. Research-agent trajectories are currently running on the pre-training and vision tasks; the post-training task is in preparation.

SIGNATURE · Pretrain

Optimizer update geometry

Design a genuinely new, scale-general optimizer — its gradient transformation, state, tensor grouping, and geometry — that improves Paloma and training-loss trajectories over the locked AdamH recipe at every rung of the 550M → 2.545B Marin ladder. The task asks for a new algorithm; changes to learning rate, momentum, or epsilon alone do not qualify.

SIGNATURE · Vision

GPIC one-epoch text-to-image

From nothing but the 100M-image GPIC corpus — one pass, no more — train any text-to-image model that beats the pinned PixelGen baseline on FD-DINOv2 at guidance 1.0. Architecture, objective, and size are free; the data budget, 256×256 output, compute cap, and frozen evaluator are not. Verifier hardened by a 13-case anti-cheat battery.

1-node tasks · crowdsourced

Community-proposed tasks on a single GPU node.

These tasks are proposed by the community and sized to a single GPU node. They are produced through an automated contribution pipeline that takes an idea to a validated Harbor task in about thirty minutes of the contributor's active time. The set is growing; the first examples and their validation logs are available in the pipeline repository.

learnability-cot1-node · posttrain ↗

Learnability-aware long/short CoT adaptation: improve a fixed Qwen2.5-3B-Instruct mathematical-reasoning SFT run by adapting only the supplied Long and Short CoT responses — length, structure, mixture, order, curriculum, compression, rewrite.

Target Beat the official 20% Long / 80% Short Mix-Long checkpoint under one fixed five-task judge protocol.
molmo2-pointing-refined1-node · vision ↗

Improve Molmo2 generated-video pointing: find a better bounded inference strategy — temporal sampling, prompting, decoding — for the fixed official Molmo2-VideoPoint-4B on generated-video visual-anomaly pointing, without touching the weights.

Target Better spatiotemporal pointing quality on the same fixed 72-case judge workload and deterministic inference protocol.

The taxonomy

Ten tracks, fifty-eight planned lanes.

The roadmap the tasks above are drawn from. Each lane is a bounded experiment inside a runnable open project, with a concrete research target stated against its own golden run.

RSI-1

Pretrain · Full-Recipe — Marin

Coordinated improvements to a complete pre-training recipe under fixed compute and evaluation. The agent edits narrow slices of a real Megatron-based stack; data, optimizer branches, schedules, batches, precision, topology, and evaluators stay locked.

Positional encoding across scaleworked example ↗

One positional-information or attention-scope mechanism, trained only at context 4096, must improve long-context modeling at every rung of a fixed six-model scaling ladder (550M → 2.545B). Continuous dependence on layer, width, head dim, or position is allowed — a per-rung lookup table is not.

Target Strictly lower LongPPL than baseline at each of six rungs; reward is the geometric mean of relative gains — one failed scale zeroes it.
Tokenizerdiscussion ↗

Improve language-model quality through tokenization alone, holding the rest of the Marin recipe fixed.

Target Better BPB at a fixed 128,256-token vocabulary, parameter budget, FLOP budget, and reported corpus bytes.
Optimizerdiscussion ↗

Design an optimizer update rule that wins after its own costs are accounted for.

Target Beat independently tuned AdamH, AdamW, and Muon once optimizer compute and memory are counted.
Initializationdiscussion ↗

Make small-model tuning decisions survive scale changes.

Target Transfer proxy-tuned hyperparameters across width and depth more reliably than standard initialization or μP.

RSI-3

Pretrain Data

Which data a model sees, how often it sees it, and how raw content becomes training units — with model training and preprocessing cost accounted together. The common controls: same model and token budget, preprocessing in the cost report, evaluation on held-out data.

DCLMupstream ↗

Data curation under fixed compute: quality scoring, deduplication, source weighting, and filter training are editable; the 400M-1x model and compute rules are fixed.

Target Exceed the DCLM-Baseline CORE score at the same training budget, reporting retained-data volume and preprocessing cost.
BabyLMupstream ↗

Learning from only 10 million words. Ordering, curriculum, repetition, objectives, distillation, and the model itself are open — external data is not.

Target Improve the BabyLM evaluation average over the BabyLlama baseline without adding external data.
SuperBPEupstream ↗

Beyond token-by-token BPE: vocabulary size, the transition to superword merging, and the merge rule, at fixed model FLOPs.

Target Improve the compression–quality frontier over standard BPE at ~500M scale, not just via a larger vocabulary.
RegMixupstream ↗

Predict a strong data mixture from cheap proxy runs: proxy allocation, regression model, mixture parameterization, and search strategy are editable.

Target Same proxy budget, better mixture — beat the released RegMix strategy on a 1B validation run.
FineWeb / FineWeb-Eduupstream ↗

Filtering for useful web text with DataTrove: quality, coverage, novelty, mixing, and curriculum on a 360M-model, 28B-token comparison lane.

Target Beat the local FineWeb-Edu golden run on held-out LM quality and educational benchmarks across multiple seeds.
Dolmaupstream ↗

A transparent multi-source corpus: the interaction of quality thresholds, deduplication, and source proportions, tested on a 1B-model, 50B-token ablation.

Target Lower held-out bits per byte and better downstream average than the default Dolma mixture at the same token budget.
DataDecideupstream ↗

Can small-model measurements rank data mixtures for larger models? Proxy metric, scaling extrapolation, checkpoint aggregation, and selection rule are open — no new training required.

Target Improve compute-matched decision accuracy on held-out mixtures, not merely fit the released observations.
DataCompupstream ↗

Multimodal data selection: a fixed 12.8M-pair pool, compute envelope, and 38-task suite; filtering, clustering, reweighting, and caption handling are editable.

Target Beat the no-filtering and basic-filtering golden runs on the 38-task average within the small-track budget.
RSI-4

Pretrain Architectures

Change model structure or parameterization while matching parameters, tokens, compute, and evaluation closely enough to attribute the gain to the architecture.

Gated DeltaNetupstream ↗

Recurrent sequence modeling with learned memory updates: gate and decay parameterization, layer mixing, and training hyperparameters, tested at 340M / 15B tokens against DeltaNet and Mamba-2.

Target Lower final validation perplexity than the released recipe without adding parameters, data, or compute.
PhysicsLM4upstream ↗

Controlled synthetic worlds testing compositional structure: layer placement, residual design, normalization, and hybrid sequence blocks against the Canon architecture.

Target Beat Canon-ABCD on accuracy and depth generalization at matched model size and tokens.
DyTupstream ↗

Transformers without normalization layers: scale parameter, temperature, activation form, and the kernels enabled by removing normalization statistics.

Target Lower validation loss or higher measured throughput than a tuned RMSNorm baseline at the same compute.
OLMo 2upstream ↗

A complete open model-development stack. The runnable slice: SFT data mixture, filtering, curriculum, packing, and training length from the released 7B model.

Target Improve the OLMES core average over the official SFT checkpoint at the same fine-tuning budget.
SmolLM 2/3upstream ↗

Small models with carefully staged data: when math and code sources enter the mixture, at a fixed ~1B model and 100B tokens.

Target Improve the combined math, code, and general benchmark average without more parameters or tokens.
OLMoEupstream ↗

Sparse experts with open routing and training traces: routing, load balancing, expert granularity, kernels, and parallel configuration from an official intermediate checkpoint.

Target More throughput or lower loss at matched compute, with stable expert utilization.
BLTupstream ↗

Byte Latent Transformer: entropy patcher, patch-length policy, latent transformer, and compute allocation between local and global modules. Metric is bits per byte, not token perplexity.

Target Match or beat a BPE Transformer's BPB at ~400M parameters and equal measured compute.
nGPTupstream ↗

Learning on normalized parameter manifolds: normalization rule, step scaling, learning-rate schedule, and nearby architectural choices — judged by speed to a fixed loss, not one hand-picked checkpoint.

Target Reach a fixed validation-loss threshold in fewer tokens than a tuned GPT baseline under the same budget.
RSI-5

Training Efficiency

Reach a target quality with less training, tuning, precision cost, or communication — and test whether decisions made on small models remain correct on large ones. Experiments must account for search cost, not just final loss.

Muonupstream ↗

Matrix-aware optimization: learning rate, momentum, Newton–Schulz iterations, orthogonalization, and parameter grouping — against an AdamW arm with its own tuning budget, measured in wall-clock as well as steps.

Target Reach validation loss 3.28 faster than tuned AdamW, or beat the released Muon config within a fixed 8-hour budget.
OLMo Model Ladderupstream ↗

Predict large-model task scores from small runs: ladder sizes, compute allocation, fitting functions, intermediate metrics, and checkpoint smoothing. The 7B/13B targets stay untouched.

Target Reduce held-out task-score error below the released two-stage method at the same total small-model FLOPs.
CompleteP / nanoGPT-mupupstream ↗

Transfer hyperparameters across depth: residual scaling, initialization, optimizer epsilon scaling, and the transfer protocol on an 8/32/64-layer grid.

Target Flatter, more accurate LR transfer across depth than SP and μP — and lower loss on the deepest target.
u-μPupstream ↗

Unit scaling for transferable, low-precision training: scaling rules, parameterization coefficients, FP8 formats, dynamic scaling, and optimizer settings.

Target Keep the best LR stable from width 256 → 2048 and shrink the FP8–BF16 loss gap at a fixed token budget.
OpenDiLoCoupstream ↗

Training across poorly connected workers: inner/outer optimizers, synchronization interval, Nesterov parameters, worker count, quantized all-reduce.

Target Improve the loss–communication frontier over DDP and the released DiLoCo recipe at matched total compute.
RSI-6

Model Systems

Turn a fixed model into a faster, more usable implementation. Speed never replaces correctness: comparisons lock workload shapes, precision, and numerical tolerances, then measure throughput, latency, bandwidth, memory, or communication directly.

FlashAttentionupstream ↗

I/O-aware exact attention: tiling, work partition, data layout, numerics, pipelining, CUDA/CuTe scheduling — with the repository's numerical tests as a hard gate.

Target Improve the throughput–memory frontier across sequence lengths without changing exact-attention outputs.
MInferenceupstream ↗

Sparse prefill for very long contexts: head-pattern selection, offline pattern search, online index estimation, and Triton/CUDA kernels — latency paired with a quality check.

Target Cut 100K–1M-token prefill latency with RULER within one point of baseline.
FlashMLAupstream ↗

Dense decoding kernels for multi-head latent attention: kernel tiling, scheduling, memory access, CUTLASS — memory-bound and compute-bound shapes reported separately.

Target Raise measured bandwidth or TFLOPS over the golden run while matching the PyTorch reference numerically.
DeepGEMMupstream ↗

FP8 GEMM for dense and MoE models: block shapes, instruction scheduling, scaling implementation, low-level CUDA — the FP8 recipe and benchmark shapes stay fixed.

Target Improve geometric-mean throughput across the locked shape suite with all correctness tests passing.
DeepEPupstream ↗

Communication kernels for expert parallelism: buffer layout, chunking, queue-pair settings, SM allocation — reporting both bandwidth and GPU resources consumed.

Target More dispatch/combine bandwidth — or the same with fewer SMs — under the same topology and correctness checks.
Liger-Kernelupstream ↗

Fused Triton kernels for LM training: add or rewrite kernels, adjust chunking, improve the integration layer — with end-to-end convergence checks, since a microbenchmark can't catch an unstable kernel.

Target Better throughput and peak memory on the same SFT workload while preserving loss and test equivalence.
DeepSpecupstream ↗

Scheduling speculative decoding: speculative length, confidence thresholds, draft scheduling, serving integration. Lossless greedy output relative to the target model is required.

Target Faster end-to-end decode on reasoning and code benchmarks, with acceptance length reported.
Zero Bubble PPupstream ↗

Pipeline scheduling: split backward into input and weight passes, rearrange schedules, interleaving, microbatch count, communication overlap — semantics and memory budget fixed.

Target Fewer measured bubbles and more throughput than 1F1B and released Zero-Bubble schedules at matched activation memory.
checkpoint-engineupstream ↗

Faster weight delivery from trainers to rollout engines: buckets, overlap, pinned memory, NCCL settings, reload interface — every tensor must match the source checkpoint.

Target Lower end-to-end weight-update latency with complete tensor-level verification.
RSI-7

SFT and Alignment

Supervised fine-tuning, preference learning, safety, and reward modeling from a fixed starting model — improving the frontier without paying an alignment tax elsewhere.

Tülu 3upstream ↗

SFT, preference optimization, and RLVR in one stack: stage order, data and curriculum, objectives, sampling, rewards, optimization — base model and total budget fixed.

Target Improve the combined reasoning + instruction-following + general-capability frontier, not one benchmark.
DPOupstream ↗

Learning directly from preferred response pairs: loss variants, temperature, length normalization, pair filtering, optimization — same SFT start and preference pairs for every arm.

Target Beat tuned DPO on held-out preference accuracy and pinned-judge win rate without degrading base capabilities.
PKU Safe-RLHF / BeaverTailsupstream ↗

Helpfulness as reward, safety violations as cost: reward/cost representation, multi-objective losses, dual updates, sampling, curriculum — reported as a frontier, not one combined score.

Target Push the helpfulness–harmlessness Pareto frontier outward with stable constraint violations at the same rollout budget.
HALOs / KTOupstream ↗

Learning from binary or unbalanced feedback: utility model, reference treatment, loss, reweighting, curriculum, sampling — with DPO and KTO as tuned controls.

Target Better held-out preference quality in noisy or imbalanced settings while retaining general ability.
SPPOupstream ↗

Preference optimization through self-play: opponent mixtures, response generation, preference construction, regularization, iterative updates — generation and training cost counted together.

Target Better held-out multi-judge win rate and stability than DPO and iterative-preference baselines at the same budget.
Reward Model Ensemblesupstream ↗

Delaying reward overoptimization: member diversity, aggregation, uncertainty penalties, policy optimization, best-of-N sampling.

Target Delay the point where proxy reward rises while true preference quality falls, at the same data and query budget.
HelpSteer 2/3upstream ↗

Reward models from multidimensional feedback: Bradley–Terry vs regression vs SteerLM-style objectives, data mixtures, filtering — on a compact 8B lane.

Target Improve RewardBench and held-out preference accuracy over a reproduced 8B golden run at the same budget.
RM-R1upstream ↗

Reward modeling as explicit reasoning: trajectory filtering, ordering, mixture, SFT hyperparameters, plus an optional small verified-reward stage within budget.

Target Beat the released Distill-7B checkpoint on RewardBench and RM-Bench within the fixed training envelope.
RSI-8

RL

RL with verifiable rewards, and agentic RL with tools and stateful environments. Rewards are cheap to score and easy to misuse — so rollout budgets, reward verification, tools, and environments stay fixed, and gains must come from learning.

PRIMEupstream ↗

Learning process rewards from policy rollouts: reward-model update frequency, weighting, difficulty-band filtering, process/result mixing, RL hyperparameters.

Target Better MATH-500 learning curve and final accuracy than PRIME and outcome-reward baselines at equal rollouts.
Understand-R1-Zero / Dr. GRPOupstream ↗

Removing biased length incentives: advantage estimation, normalization, sampling temperature, response limits, difficulty mixture — accuracy and length reported together.

Target Improve MATH-500 and AIME-24, or match them with fewer generated tokens and less length inflation.
RAGEN / StarPOupstream ↗

Stable RL in interactive environments: uncertainty filtering, clipping, KL control, rollout sampling — where vanilla StarPO improves then collapses.

Target Higher final Sokoban success with the late-training collapse prevented, across multiple seeds.
Search-R1upstream ↗

Learning when to retrieve: query formation, retrieval penalties, search rounds, reward shaping, the PPO/GRPO update — retrieval infrastructure locked.

Target Better average exact match over seven held-out QA datasets at the same rollout budget.
Logic-RLupstream ↗

Curriculum design on procedurally generated Knights-and-Knaves problems with exact verification: difficulty mixture, harder generated instances, format rewards, GRPO tuning.

Target Better accuracy at all difficulty levels, with positive transfer to held-out math benchmarks.
DAPOupstream ↗

Stabilizing large-scale reasoning RL: asymmetric clipping, dynamic sampling, token-level losses, overlong-response shaping — testable in a one-day 7B run.

Target Exceed the local DAPO AIME-24 golden run while preventing entropy collapse and response-length blowup.
RSI-9

Vision Understanding

Reusable visual and multimodal representations, and more efficient visual inputs. Representation quality is measured outside the pre-training objective — fixed probes and held-out domains, so a lower loss can't substitute for better transfer.

MAEupstream ↗

Masked autoencoding: mask ratio and pattern, decoder size, target normalization, augmentation, schedule, data pipeline — with the downstream probe fixed.

Target Better linear-probe or fine-tuning accuracy at the same pre-training epochs or GPU-hours.
OpenCLIPupstream ↗

Open image–text contrastive training: loss, encoders, pooling, tokenization, resolution, curriculum, regularization, kernels — on a pinned open subset with a local ViT-B/32 golden run.

Target Better retrieval and zero-shot aggregate at fixed data, FLOPs, and model size, with stable training.
I-JEPAupstream ↗

Predicting representations rather than pixels: context/target sampling, predictor and encoder design, teacher EMA, masking, curriculum, optimization.

Target Better k-NN and linear evaluation under the same ImageNet and compute envelope.
DeepOCRupstream ↗

Compressing documents into fewer visual tokens: projector, 16× compressor, dynamic tiling, resolution policy, data proportions — decoder and public data fixed.

Target Better OmniDocBench / olmOCR-bench quality–token frontier than the released checkpoint.
DiT / SiT / REPAupstream ↗

Representation alignment for generative training: target encoder, aligned layer, projection head, loss weight, schedule — SiT-B/2 backbone, step budget, and sampler fixed.

Target Lower FID than vanilla SiT and the released REPA recipe at 400K steps and matched wall-clock.
RSI-10

Vision Generative Modeling

Balance output quality, training cost, and sampling cost together. A method that lowers FID with far more denoising steps has not moved the frontier — comparisons lock data and training compute and report quality alongside sampling cost.

micro_diffusionupstream ↗

Strong text-to-image training on a small budget: masking, patch mixing, data selection, resolution stages, optimization — inside a fixed GPU-time envelope.

Target Lower zero-shot COCO FID or better GenEval within the same end-to-end compute budget.
VARupstream ↗

Next-scale autoregressive generation: LR and weight-decay schedule, scale curriculum, loss weighting, augmentation, progressive training — d16 architecture and tokenizer fixed.

Target Reach d16 FID in fewer steps, or lower FID at the same epochs and wall-clock while preserving IS.
Latent Diffusionupstream ↗

Generation in a compressed space: autoencoder, latent representation, denoiser, conditioning, noise path, sampler, guidance — each gain must say whether it came from training, compression, or costlier sampling.

Target Improve the quality–training-cost–sampling-cost frontier over a local open-data golden run.
Consistency Modelsupstream ↗

One- and few-step generation: consistency objective, teacher–student distillation, time sampling, solver, architecture, curriculum — shown across several function-evaluation counts.

Target Better FID at one and a few steps without increasing the ImageNet-64 training budget.
MARupstream ↗

Autoregressive generation with continuous tokens: patch representation, DiffLoss, prediction order, masking schedule, grouping, conditioning, sampler — on a full ImageNet-256 training and FID loop.

Target Better FID, sampling cost, or stability than the local MAR + DiffLoss golden run at matched FLOPs.

Task anatomy

What a task must satisfy before release.

Once a project enters task design, the pinned repository is the scientific source of truth for the model, data, configuration, training procedure, evaluator, and baseline.

Which projects qualify

Fully openEverything needed for the lane is public and usable — runnable code, configuration, required model/checkpoint and data assets, and an evaluation path.
InfluentialThe project materially shaped its cohort through adoption, citations, community use, or an important open release.
ReproducibleThe author-released path runs end to end in a documented environment. Missing assets or unverifiable metrics stop admission.
ResearchableIt exposes a meaningful open research space where the agent's decisions affect the result.
VerifiableA separate verifier can evaluate the final artifact with fixed metrics and integrity constraints.

The Harbor package

instruction.mdScientific objective, setup, baseline, iteration loop, and submission requirements — with pinned commits, immutable asset revisions, entrypoints, and the resource envelope.
policy.yamlEditable scope, locked variables, network boundary, and hard-zero violations for reward hacking.
environment/project/The pinned author repository, used as the editable workspace.
tests/Trusted verifier orchestration, integrity gates, fixed evaluation, and reward mapping — run in a separate clean image.

Hard-zero policy violations

  • Reward-path tampering — modifying or bypassing the reward path.
  • Evaluation leakage — training on, filtering on, or hardcoding evaluation examples.
  • Budget overrun — exceeding registered compute or wall-clock limits.

Verification path

  • Reuses the author's evaluator when possible, in a separate clean image.
  • Diffs the candidate workspace against a clean pinned checkout; protected-path changes are rejected.
  • Applies programmatic and LLM-as-judge integrity checks — failing closed to zero on a hard violation.
  • Recommended envelope: single runs on ≤ 64 H100s, ≤ 8 hours; the iterative research process itself is uncapped.
