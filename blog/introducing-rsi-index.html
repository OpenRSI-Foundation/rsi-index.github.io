Introducing the RSI Index

The RSI-Index program turns representative, fully open model-development projects into auditable environments in which an AI research agent repeatedly improves a real workflow against a fixed evaluator. The question is not whether an agent can tune a toy proxy — but how much it can improve a human-built, open recipe while preserving the experiment's scientific contract.

// 01The last puzzle before ASI

To take ASI seriously is to accept a weak-to-strong premise: human intelligence can create a process that eventually produces intelligence beyond human capability. The current vocabulary for that premise — RSI, self-evolve, autoresearch — names the same loop: an agent proposes a hypothesis, implements it, and evaluates the result against a verifiable objective.

The central question is whether this loop can move beyond the best known human-designed method and reliably extend the scientific frontier. Answering it requires careful measurement, and building that measurement is the purpose of this project.

// 02Scaling insights

Scientific progress is limited not only by compute and data, but by the bandwidth of insights. A human researcher holds a few hypotheses in mind and runs a few experiments a week. An agent scales both the generation of candidate ideas and their implementation, and so sweeps a larger region of method-space. That is the ambition of RSI — and it is exactly the thing worth measuring carefully.

// 03What we're building

RSI-Index is an evaluation-and-research-production loop for model development:

Open projects  →  Agent environments  →  RSI Index

In an RSI task, an agent receives the editable source for a real open project, a fixed budget, a concrete experiment, and a verifier it cannot alter. Three commitments shape every task:

  • Optimization, not reproduction. The agent takes over the cluster and starts from the original codebase, data, and checkpoints to improve the pipeline — the deliverable is an artifact that outperforms the original recipe.
  • Scientific discovery, not parameter sweeping. RSI goes beyond hyperparameter search. It tests whether agents can form hypotheses, modify real model-development methods, learn from experiments, and produce gains that remain meaningful under a fixed scientific contract.
  • Production scale, not toy scale. Tasks reflect problems frontier researchers care about, at model, data, and system scales where improvements matter — and transfer to real training and deployment rather than existing only on toy proxies.

The score itself is deliberately simple: RSI improvement is the performance of the agent-selected final artifact relative to a matched, task-pristine human-recipe baseline. The "human baseline" is the original authors' released recipe, rerun unchanged in the same task environment. That frozen rerun — not the paper's claim — is the ranking baseline.

// 04From open projects to agent environments

An RSI task is a bounded experimental lane extracted from a runnable open project: an end-to-end run, a repository-published ablation or deployment lane, or a faithful, separately versioned slice of a larger pipeline that preserves the causal mechanism and evaluation path of the source project.

Projects pass five gates before task design begins — fully open, influential, reproducible, researchable, and verifiable. Once a project is admitted, the pinned repository becomes the scientific source of truth for the selected task's model, data, configuration, training procedure, evaluator, and baseline.

Every task ships in Harbor format: an instruction.md that states the objective and the frozen setup, a policy.yaml that draws the editable boundary, the pinned author repository as the workspace, and a verifier that runs in a separate clean image. The verifier diffs the candidate workspace against a clean checkout, applies programmatic and LLM-as-judge integrity checks, and fails closed to zero on a hard violation — reward-path tampering, evaluation leakage, or budget overrun.

// 05Where the program stands

The framework is now running. Three signature tasks — one per domain, built as complete Harbor packages with hardened, adversarially tested verifiers — anchor the benchmark, and research-agent trajectories are running on them now:

  • Pre-training — optimizer update geometry. Design a genuinely new, scale-general optimizer that beats the locked AdamH recipe at every rung of the 550M → 2.5B Marin scaling ladder. Algorithm discovery, not scalar retuning.
  • Vision — GPIC one-epoch text-to-image. From nothing but a 100M-image corpus, exactly one pass, train any text-to-image model that beats the pinned PixelGen baseline on FD-DINOv2 at guidance 1.0 — architecture, objective, and size all free.
  • Post-training — flagship in preparation. The third signature environment, on a full open post-training stack, is being finalized.

Alongside them, a growing set of 1-node tasks — community-proposed environments sized to a single GPU node — is expanding through an automated crowdsourcing pipeline that takes a contributor from idea to a validated Harbor task in under an hour of active time. An agent drafts the proposal with you, and a review agent evaluates it in a GitHub Discussion. If it is rejected, the review's reasons can be handed to your own coding agent for revision; once it is accepted, a private task repository is created for you under the organization and you receive an email. A bundled validator then checks the task end to end. The first crowdsourced tasks and their validation logs are already in the pipeline repository.

We continue to seek partnerships with frontier labs for the compute to scale task design — and for every project we build on, we invite the original authors to review the environment that carries their recipe.
